# Known Issues & Resolutions

## Recent Issues Addressed

| # | Scraper/Area | Issue | Root Cause | Resolution |
| --- | --- | --- | --- | --- |
| 1 | Walmart | "Robot or Human" popup on every page load, even with `undetected_chromedriver` | Walmart's PerimeterX/HUMAN bot detection fingerprints automation/browser behavior and may still challenge `undetected_chromedriver` sessions. UA/header/cookie/session reputation mismatches can trigger persistent blocks. | Kept Selenium + `undetected_chromedriver` for primary path, added challenge detection + timed waits + graceful skip, and added per-item HTTP fallback parsing to reduce total data loss during blocked runs. |
| 2 | Walmart | Location-specific store pricing not set | The store-finder flow required Selenium interaction which was blocked by bot detection. | Removed location selection. Walmart.com returns local prices based on IP geolocation, which is sufficient for comparison. |
| 3 | Aldi | Scraper returns zero results, all CSS selectors fail | Aldi US migrated to an Instacart-powered storefront. `new.aldi.us` now redirects to `www.aldi.us/store/aldi/storefront`. Old selectors (`product-teaser-item`, `product-tile__brandname`, etc.) no longer exist. | Rewrote scraper to use the same Instacart card-parsing approach as Publix (Selenium DOM interaction with `<li>` product cards). |
| 4 | Aldi | `ElementClickInterceptedException` on search bar | Instacart overlay div blocks native Selenium `.click()` on the search input. | Added JS click fallback: `driver.execute_script("arguments[0].click();", element)`. |
| 5 | Publix | Location selector code broken / unreliable | The Instacart pickup/delivery modal used fragile XPath selectors targeting dynamically generated class names that changed frequently. | Removed location selection entirely. Added a lightweight popup dismisser that clicks "Confirm" on the default choice to move past the modal. |
| 6 | Publix | Overlay blocks search bar after popup dismiss | Instacart renders multiple stacked popups; dismissing one can reveal another. The search bar remains covered by an overlay div. | `_dismiss_landing_popup` now loops up to 5 rounds clicking confirm-style buttons, then explicitly waits for the search bar to become clickable before proceeding. |
| 7 | Publix | Cannot convert to HTTP-only scraping | Publix delivery is a fully client-side rendered Instacart SPA. HTML contains no product data; prices load via async GraphQL calls to `internal-api.icprivate.com`. | Kept Selenium. The GraphQL API uses persisted query hashes and auth tokens that are more fragile to maintain than the browser approach. |
| 8 | App | `KeyError: "['Aldi'] not in index"` crash in Streamlit | `app.py` pivot table hardcoded `["Aldi", "Publix", "Walmart"]`. When any scraper returned no results, the column did not exist. | Made store columns dynamic; missing stores are filled with zeros/dashes instead of crashing. |
| 9 | Data Pipeline | `daily_basket.csv` schema drift after first run | New rows introduced extra/trailing fields, shifting `clean_price`, `normalized_qty`, `brand_type`, and `category` into wrong columns. | Added schema normalization/imputation workflow and standardized output column order to match canonical pipeline fields. |
| 10 | Walmart | Corrupted parsed prices (e.g., `$448current price $4.48`) | Fallback extraction captured concatenated text blobs; generic first-number parsing picked wrong numeric token (`448`) instead of actual price (`4.48`). | Improved extraction logic in scraper and enrichment parsing to prioritize `current price`/decimal patterns and ignore concatenation artifacts. |
| 12 | Data Quality | Irrelevant product contamination in category searches | Search terms (especially bananas/eggs) included non-target matches (chips, muffins, yogurt, cheese sticks), distorting representative prices. | Added stricter keyword relevance filtering and selection guards before downstream aggregation/imputation. |
| 13 | Data Quality | Unrealistic low-value noise + unit interpretation edge cases | Synthetic variability and mixed unit contexts (per-lb/per-each) produced suspicious cents-level prices in plotted totals. | Added guardrails for variability magnitude and stricter unit-normalization checks before accepting adjusted values. |
| 14 | Tooling | Windows Unicode/BOM issues in local scripts | Console cp1252 encoding failed on Unicode symbols; PowerShell CSV writes introduced BOM/quoted header artifacts affecting downstream parsing. | Replaced Unicode test markers with ASCII output and added CSV cleanup/UTF-8-safe handling in helper scripts. |
| 17 | Publix | Location modal: `streetAddress` never appears; scraper stuck after opening modal | Instacart UI requires **Change store** → **Near** (button with span like “Near 35401”) before the address field exists. A prior **Pickup** step matched unrelated header text and skipped the real flow. Modal content also lives in portals; timing matters. | Removed the Pickup step for this flow. After Change store, `WebDriverWait` for `//button[.//span[contains(text(), 'Near')]]`, then JS click Near, then zip entry. Change store uses parent `<button>` when the hit is the inner `div`. |
| 18 | Publix | Change store control not responding to clicks | Text lives in `<div class="e-mf50rh">`; clicking the div does not reliably trigger the dialog. | Prefer clicking the parent `<button>` (`aria-haspopup="dialog"`) when the located element is the inner div. |
| 19 | Publix | Change store / header elements not ready immediately after navigation | Full storefront hydration can lag; lookups ran before the header location controls were stable. | `time.sleep(3)` immediately after `driver.get()` before waiting for “Change store” / fresh-flow UI. |
| 20 | Tooling | Hard to diagnose Publix location failures (which step failed, no DOM snapshot) | One-shot runs gave little visibility into modal vs main page state. | Added `old/run_publix_location_debug.py`: step-by-step flow with PNG + HTML under `debug_steps/`, optional `--pause` and `--stop-after N`. |
| 21 | Data Pipeline | Daily run crashed during enrichment with `ValueError: could not convert string to float: '.'` | Unit parsing regex captured a standalone period from strings like `lb.` and attempted `float('.')`. | Added safe numeric token parsing in `scrapers/units.py` (`_first_float`) and fallbacks so invalid tokens are skipped without crashing runs. |
| 22 | Driver/Runtime | Scraper crash: ChromeDriver version mismatch (`driver 145` vs installed Chrome `144`) | Driver auto-resolution pulled an incompatible ChromeDriver for local browser version, causing session creation failure. | Added installed-Chrome detection and version-pinned driver selection in `scrapers/utils.py`; Walmart `undetected_chromedriver` now receives `version_main` from detected major version. |
| 23 | Walmart | No Walmart rows appended to `daily_basket.csv` on failed runs | Walmart scraper exception was swallowed into a generic "A scraper crashed" log, making missing-store output ambiguous. | Added scraper-specific crash reporting in `main.py` (`Aldi/Publix/Walmart scraper crashed`) and a focused `run_walmart_only.py` check path to validate Walmart independently. |
| 24 | Publix | Intermittent `StaleElementReferenceException` while iterating result cards | Result list re-rendered while looping over previously captured `li` elements. | Switched to index-based iteration with re-fetch on each pass and retry-on-stale reads in `scrapers/publix.py`. |
| 25 | Publix | Bananas returned zero matches despite visible banana products | Title extraction picked badge text (e.g., "Best seller", "Gluten free") instead of product name, so keyword filter rejected valid cards. | Updated title selection to prefer lines matching search keywords (with singular/plural matching), widened card scanning, and added produce-style price handling (`per lb`, `per each`, `Current price`). |
