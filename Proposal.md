### Project Proposal: Smart Grocer
Grocery prices can vary by location and retailer, yet consumers lack the tools to efficiently compare costs for their specific needs without manually visiting each grocer’s website, entering their location, and evaluating the available options. To address this, I will develop the Smart Grocer, a locally run program that allows users to input their zip code or address and grocery list. The program will automate the data collection process by scraping real-time, location-based prices from Aldi, Publix and Walmart, as an MVP set of retailers. It will then provide users with a data-driven "Best Shopping Plan" that identifies the most cost-effective retailer or set of retailers for their specific basket of goods. A possible extension includes integrating driving time via Google’s Routes API to assess the total cost of price, time and fuel for the optimal shopping plan.
Data collection will be performed by a Python web-scraping engine using Selenium, Chromedriver, and parallel processing. I will implement algorithms to navigate dynamic web pages and extract product data points such as product name, price, unit size, and availability, simultaneously across retailers. This raw data will be filtered using keyword-matching algorithms to ensure relevance to the user’s search terms. The application will be accessible via a Streamlit User Interface (UI) for the ease of the user. Validated data will be persisted in a local SQLite database. I will also use this database to log a scheduled daily query of a standard item set to build a longitudinal dataset for analysis.
Using the aggregated data, I will conduct a formal statistical analysis. An initial list of research questions are the following:
Controlling for product-specific price variance, is there a statistically significant difference in the mean total basket cost between Aldi, Publix, and Walmart?
Does the "Retailer Effect" on price remain consistent across different categories of goods (e.g., Produce vs. Pantry)?
How much do grocery prices vary between stores within the same geographic area?
Is there a specific day of the week that exhibits statistically lower prices for basic goods?
Can total shopping cost be minimized by visiting multiple stores, even when accounting for estimated fuel costs?
Which individual products or categories exhibit the highest price volatility over time?
Which retailer exhibits the highest price volatility for staple goods over time?
What is the prevalence and price advantage of generic, store brand items in the top search results?
Can future prices be predicted based on historical pricing trends in the data?
I expect to utilize multiple statistical methods to evaluate these questions. The core analysis will rely on a Randomized Complete Block Design (RCBD) experiment, treating items as "blocks" to isolate differences in retailers while controlling for the high variance between different types of goods. To analyze differences, I will initially perform a Repeated Measures ANOVA to test for a statistically significant difference in mean basket costs. I will assess model assumptions, checking for normality of residuals and homogeneity of variance. If assumptions are violated, I will pivot to non-parametric tests such as the Friedman Rank Sum Test or implement a Robust Bayesian Hierarchical Model using Student-t distributions to ensure conclusions are resilient to anomalies.
This project will produce software to perform real-time analysis for the user via the Streamlit dashboard, displaying comparative bar charts and a "Total Savings" metric. It will also communicate statistical findings in a final report and presentation. This will address a practical consumer problem for a variety of groups, including college students interested in saving money. It demonstrates applied data science skills including web scraping, data cleaning, machine learning, and optimization, and results in a tool that is accessible and useful to non-technical users.
